# 标记生效范围与快捷标记入口设计

## 背景
当前应用已经支持在桌面双击后对当前轮播壁纸进行标记，但实际使用中仍有两个痛点：

1. 桌面多页滑动时，双击可能在非首页误触发。
2. 用户希望在不依赖桌面双击的情况下，直接从快捷入口标记“当前正在显示的壁纸”，便于配合 FooView 等外部工具使用。

本设计的目标是同时提供：
- 仅首页允许双击标记的可选限制。
- 应用图标快捷动作入口。
- 可被外部工具直接唤起的快速标记入口。

## 目标
1. 新增“仅首页生效”的可配置开关。
2. 保留现有双击标记能力，但在开关开启时，仅在桌面第一页允许触发。
3. 提供一个静默式快捷标记入口，触发后立即标记并退出，不弹确认页。
4. 同时支持：
   - 应用图标长按快捷动作。
   - FooView 等外部工具通过显式组件调用该入口。
5. 尽量复用现有数据库与服务逻辑，不引入新的复杂同步机制。

## 非目标
1. 不尝试识别不同 Launcher 的真实“主屏页”语义，只基于壁纸偏移量判断第一页。
2. 不增加确认弹窗、预览弹窗或悬浮窗。
3. 不新增 App Widget；外部触发通过 Activity 入口实现。
4. 不修改现有已标记图库结构。

## 方案比较

### 方案 A：统一透明 Activity 入口 + 服务暴露当前壁纸引用（推荐）
做法：
- 新增一个透明、无界面的 `QuickMarkActivity`。
- 该 Activity 既作为应用快捷动作目标，也作为外部工具调用入口。
- `MyWallpaperService` 在壁纸切换时保存“当前显示壁纸”的可读取引用。
- `QuickMarkActivity` 启动后直接读取当前壁纸引用，写入数据库标记状态，Toast 提示后立即退出。

优点：
- 一个入口同时覆盖快捷菜单和外部调用，结构最简单。
- 触发速度快，符合“静默式”要求。
- 不需要 UI 预览，也不依赖主界面已经打开。

缺点：
- 依赖壁纸服务正确维护“当前显示壁纸”的最新引用。
- 如果服务未运行或引用为空，需要给出失败提示。

### 方案 B：快捷入口发广播，由服务处理标记
做法：
- 快捷动作和外部工具都发送广播。
- `MyWallpaperService` 内部接收后直接执行标记。

优点：
- 逻辑集中在服务内部。

缺点：
- 广播可见性、生命周期与 Android 版本限制更复杂。
- 外部工具适配体验不如启动显式 Activity 稳定。

### 方案 C：快捷入口拉起主界面，由主界面代为标记
做法：
- 快捷入口先启动主界面，再由主界面协调数据库写入。

优点：
- 利用现有界面层依赖，容易接线。

缺点：
- 干扰操作，明显不符合“静默式”诉求。
- 启动慢，体验最差。

### 结论
采用**方案 A**。它最符合当前需求，也最容易同时兼容系统快捷动作和外部工具显式调用。

## 整体架构

### 1. 设置层
在 `SharedPreferences("settings")` 中新增：
- `mark_only_on_first_page: Boolean`，默认 `false`

设置页新增一个开关项，用于控制双击热区是否仅在首页生效。

### 2. 壁纸服务层
`MyWallpaperService` 继续负责：
- 记录最近一次桌面偏移量 `lastXOffset`
- 处理双击时间与两次点击距离判断
- 执行当前壁纸标记动作

新增职责：
- 在切换/显示新壁纸时维护当前壁纸路径或 URI 的内存态引用
- 在双击判定前读取 `mark_only_on_first_page`
- 当开关开启时，仅在偏移量接近第一页时允许进入标记逻辑

首页判定规则：
- 使用 `xOffset <= 0.01f` 作为第一页判定阈值
- 使用阈值而不是严格等于 0，是为了兼容 Launcher 浮点误差

### 3. 快捷入口层
新增 `QuickMarkActivity`：
- 主题透明，无布局或仅保留最小根布局
- `exported=true`
- 可通过显式组件名启动
- `launchMode` 采用单次触发即可完成的轻量模式

触发来源：
1. `shortcuts.xml` 中定义的应用快捷动作“标记当前壁纸”
2. FooView 等工具通过包名 + Activity 类名显式调用

### 4. 数据层
继续复用 Room：
- 通过当前壁纸的路径/URI 查询数据库记录
- 将该记录的 `isMarked` 更新为 `true`

如果当前壁纸已经是已标记状态，则保持幂等，不做额外副作用。

## 详细数据流

### A. 双击标记（首页限制开启时）
1. 用户在桌面触摸。
2. `MyWallpaperService` 接收触摸事件。
3. 服务先执行现有的双击时间窗口与偏移距离校验。
4. 若 `mark_only_on_first_page=true`，则额外校验 `lastXOffset <= 0.01f`。
5. 若不满足第一页条件，则本次双击直接忽略，不标记。
6. 若满足条件，则继续走现有标记逻辑。

### B. 快捷动作 / 外部触发标记
1. 用户点击应用快捷动作，或 FooView 启动 `QuickMarkActivity`。
2. `QuickMarkActivity` 启动后读取服务保存的“当前壁纸引用”。
3. 若引用为空：
   - Toast：`当前壁纸信息不可用`
   - 立即 `finish()`
4. 若引用存在：
   - 在 IO 线程访问数据库
   - 将对应壁纸标记为已收藏/已标记
   - Toast：`已标记当前壁纸`
   - 立即 `finish()`

## 组件边界

### `MyWallpaperService`
负责：
- 判定当前桌面偏移量
- 维护当前显示壁纸引用
- 处理桌面双击触发

不负责：
- 响应系统快捷动作清单
- 处理外部显式 Activity 调用

### `QuickMarkActivity`
负责：
- 作为统一快捷入口
- 拉取当前壁纸引用
- 执行一次性数据库标记
- 向用户返回轻提示

不负责：
- 管理双击手势
- 显示主界面或预览 UI

### `MainActivity`
负责：
- 暴露“仅首页生效”设置项
- 如有需要，为用户展示快捷入口说明文案

不负责：
- 执行快捷标记本身

## 错误处理
1. **服务未运行 / 当前壁纸引用为空**
   - 行为：Toast 提示并退出
   - 原因：应用可能刚开机、壁纸服务尚未准备好，或当前状态尚未写入

2. **数据库中找不到当前壁纸记录**
   - 行为：Toast 提示 `当前壁纸未收录，无法标记`
   - 说明：可能是扫描未完成，或当前壁纸来自未纳入数据库的来源

3. **重复标记**
   - 行为：视为成功，仍提示已标记或已在标记列表中
   - 说明：保持幂等，避免因为状态已存在而报错

4. **外部工具重复快速调用**
   - 行为：每次调用独立处理
   - 说明：由于操作是幂等的，重复调用不会破坏数据

## 测试与验证

### 功能验证
1. 在设置页开启“仅首页生效”。
2. 回到桌面第一页，在热区内双击，确认能标记。
3. 滑到第二页或更后页，在同一热区双击，确认不会标记。
4. 关闭“仅首页生效”后，再次在非首页双击，确认恢复可标记。
5. 长按应用图标，点击“标记当前壁纸”，确认 Toast 成功并写入数据库。
6. 使用 FooView 或等价工具显式启动 `QuickMarkActivity`，确认也能成功标记。
7. 在当前壁纸尚未收录到数据库时触发快捷标记，确认提示失败而不是崩溃。

### 回归验证
1. 现有双击偏移容差设置仍然生效。
2. 现有“滑页时不触发标记”逻辑仍然生效。
3. 已标记图库列表仍能看到新加入的标记项。
4. 不影响现有壁纸切换与扫描逻辑。

## 涉及文件
- `app/src/main/java/com/example/wallpaper/service/MyWallpaperService.kt`
  - 增加首页限制判定
  - 维护当前壁纸引用
- `app/src/main/java/com/example/wallpaper/ui/MainActivity.kt`
  - 增加“仅首页生效”设置项
- `app/src/main/AndroidManifest.xml`
  - 注册 `QuickMarkActivity`
  - 接入快捷动作资源
- `app/src/main/res/xml/shortcuts.xml`
  - 定义“标记当前壁纸”快捷动作
- `app/src/main/java/com/example/wallpaper/ui/QuickMarkActivity.kt`
  - 新增统一快捷标记入口
- 可能涉及 DAO / Repository 文件
  - 如现有 DAO 缺少按路径标记的更新方法，则补充最小更新接口

## 实施原则
1. 尽量复用现有 `SharedPreferences` 与 Room 模式。
2. 不引入新的后台常驻组件。
3. 快捷入口只做一件事：静默标记当前壁纸并退出。
4. 首页限制仅作为附加过滤条件，不改动既有双击判定主体。

## 后续实现建议
实现时优先按以下顺序推进：
1. 先补 DAO 更新接口与服务当前壁纸引用维护。
2. 再补 `QuickMarkActivity`，先通过内部启动验证标记链路。
3. 然后接入 `shortcuts.xml` 与 Manifest 导出配置。
4. 最后把“仅首页生效”设置项接到 `MainActivity` 与服务逻辑。
